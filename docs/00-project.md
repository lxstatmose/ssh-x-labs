# Паспорт проекта SSH-X

## Название и происхождение

SSH-X — настольный клиент удалённого доступа и передачи файлов. Собственный проект пользователя lxstatmose, выделенный в отдельный учебный репозиторий: https://github.com/lxstatmose/ssh-x-labs. Исходный проект: https://github.com/lxstatmose/ssh-x. Для лабораторной изучен архив ветки main с идентификатором ecec4f5, версия приложения в package.json — 1.0.1. Дата анализа: 30 октября 2026 года. Учебный репозиторий — отдельная копия собственного проекта. Название папки само по себе не определяет связь fork на GitHub; в паспорте фиксируется авторское происхождение. Изменения на GitHub не выполнялись.

## Назначение и решаемая проблема

Приложение объединяет удалённый терминал, работу с файлами на сервере и локальную оболочку в одном интерфейсе macOS. Оно позволяет обслуживать несколько серверов без постоянного переключения между отдельным терминалом и файловым клиентом, сохранять параметры подключений и открывать независимые рабочие панели.

## Целевые пользователи и роли

Целевые пользователи — системные администраторы, разработчики и владельцы серверов/NAS. В приложении у них одна роль: пользователь клиента, управляющий собственными подключениями. Эти группы не считаются разными ролями доступа. Внешние системы — SSH/SFTP-, FTP/FTPS- и Telnet-серверы; локальная оболочка предоставляет локальное исполнение команд. Проект соответствует варианту курса «одна роль и взаимодействие с внешней системой». Учётные записи и права на удалённые файлы определяются внешним сервером.

## Три основные функции

1. Подключение к серверу по SSH и исполнение команд в терминале.
2. Просмотр и изменение удалённых файлов через SFTP или FTP/FTPS.
3. Управление сохранёнными профилями и параллельной работой во вкладках и панелях.

Локальная оболочка и Telnet дополняют эти функции. Карта ниже содержит десять укрупнённых пользовательских функций.

## Технологический стек и лицензия

Главный процесс: Electron, JavaScript/CommonJS; интерфейс: React, TypeScript, CSS; терминал: xterm.js и addon-fit; SSH/SFTP: ssh2; FTP/FTPS: basic-ftp; локальная оболочка: node-pty. Сборка интерфейса — Vite, дистрибутива — electron-builder. Контроль качества — TypeScript и ESLint; CI/CD описаны в GitHub Actions.

В исходном package.json зависимости заданы диапазонами, существующий package-lock.json фиксирует дерево зависимостей. В рамках лабораторной синхронизирована версия корневого пакета в lock-файле: 1.0.0 → 1.0.1; версии зависимостей не менялись. Точные версии прямых зависимостей перечислены в evidence/versions.json. Проверенная среда: Node.js 26.12.0, npm 11.20.0; .nvmrc фиксирует версию Node.js. Существующий CI использует Node.js 20 и 22 — совместимость нового lock-файла с этими окружениями пока не проверена.

Лицензия основного проекта — ISC, правообладатель в LICENSE: Copyright (c) 2026 lxstatmose. Существующий LICENSE нужно сохранить. Встроенный шрифт JetBrains Mono сопровождается src/renderer/assets/NOTICE.md; лицензии зависимостей сохраняются отдельно.

### Данные и внешние зависимости

Серверная БД отсутствует. Профили находятся в sessions.json внутри Electron app.getPath('userData'); ключ для шифрования выводится из локального файла .encryption-secret, а ключи серверов сохраняются в known_hosts в том же каталоге. Секреты шифруются AES-256-GCM. Хранение секрета рядом с данными не заменяет защиту учётной записи ОС. Интерфейсу передаются метаданные профиля без расшифрованных паролей. Активные соединения находятся в памяти процессов.

Работа с удалёнными протоколами требует доступного сервера и учётной записи. Платные API и облачная БД для базовой работы не нужны. Локальный терминал использует оболочку из SHELL, по умолчанию /bin/zsh на macOS, и стартовый каталог пользователя.

### Конфигурация и поток выполнения

package.json указывает main.js; он создаёт окно и загружает preload.js. В режиме разработки ELECTRON_DEV=true и VITE_PORT задаются dev.js, окно загружает Vite. В собранном режиме загружается dist/renderer/index.html. React вызывает window.api, preload переводит вызовы в IPC, главный процесс обращается к менеджеру протокола. Данные и события возвращаются в интерфейс.

Параметры сервера вводятся в UI и сохраняются в профиле. Для окружения локальной оболочки важны SHELL, PATH, LANG и LC_ALL. Релизные секреты подписи и нотариализации нужны только для соответствующего процесса выпуска, а не для разработки.

### Первые наблюдения для issues

Тексты находятся в handin/ISSUES.md. На GitHub они не создавались.

1. В исходном .nvmrc указана только основная версия 20, package.json допускает >=20, а CI использует 20/22. Требуется согласовать точную проверенную среду; для локальной проверки использованы Node.js 26.12.0 и npm 11.20.0, .nvmrc уточнён до 26.12.0.
2. Автоматические регрессионные тесты протоколов и сохранения профилей отсутствуют.
3. ESLint сообщает 8 предупреждений о зависимостях React Hooks; следует проверить сценарии смены каталога, соединения и размеров терминала.
4. Проверку ключа SSH-хоста следует проверить интеграционно: приложение подписывается на hostkey, а установленный ssh2 использует настройку hostVerifier. Это наблюдение по коду, без испытания на тестовом сервере; не является подтверждённым воспроизведением атаки.

### Предварительный объём семестра

Включить: воспроизводимую установку; SSH по паролю и ключу; проверку доверия к хосту; сохранение/редактирование/удаление профилей; локальную оболочку; вкладки/панели; SFTP-навигацию и передачу файлов; обработку отказа аутентификации и разрыва соединения. Большая часть функций уже реализована: предмет семестра — их формализация, проверка и выбранные исправления.

За пределами обязательного развития: jump-host, туннели и SOCKS, ssh-agent и полноценный MFA, импорт ~/.ssh/config, broadcast-ввод, темы, shell integration, рекурсивный двухпанельный менеджер, Windows/Linux и коммерческая подпись. Существующие FTP/FTPS и Telnet сохраняются, но их расширение не входит в обязательный объём; базовые сценарии учитываются в обзоре и при доступности стенда — в регрессии.

Окончательный объём утверждается в лабораторной № 2. Проект и план ещё не согласованы с преподавателем; product должен оставаться открытым до реального одобрения. Слияние и тег lab-1 выполняет пользователь.
